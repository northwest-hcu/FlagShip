# Editorの操作構造案

## 提案の位置づけ

この文書は操作構造の設計と実装時の確認条件を記録する。P0〜P2の操作変更をEditorへ反映した。CanvasとFlowの並列関係、4表示形式、平坦なRegistryとLibrary filter、空のFlow作成、Nodeの自由配置と明示的な整理、Registry・Treeの個別縮小、Preview限定のWATCH・ログ、Containerの初期横並びを維持する。

## 目的

初めて使う人が、いま編集している面、選択中の対象、追加先、操作後の結果を画面から読み取れるようにする。CanvasとFlowは独立した編集対象のまま、単独・上下分割・左右分割で同じ操作規則を使う。

変更前は、分割表示で操作した面に合わせて左欄の内容が切り替わる理由が見えにくく、Registryの「＋」の追加先も明示されていなかった。Canvasの上下左右ドロップで生まれる自動レイアウトはTreeでは省略され、Detailsの全フィールドが閉じた状態で始まっていた。これらを優先して整理した。

設計の根拠は「現在の状態を見せる」「選択肢を思い出させるより見せる」という[NN/gのユーザビリティ原則](https://www.nngroup.com/articles/ten-usability-heuristics/)と、ドラッグ操作にクリック等の代替を用意する[WCAG 2.2の解説](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements/)を参照する。以下の画面構造は、これらを現在のEditorへ適用した提案である。

## 全体構造

```text
Header      Canvas | Flow | 上下分割 | 左右分割
Context     編集対象: Canvas / Flow   Page・slot または Flow名   Preview状態
┌ 左欄 ────────────┬ 作業領域: Canvas / Flow（単独または分割）────┐
│ Registry          │ 各面のツールバー・配置領域     │ Inspector   │
│ 検索・Library filter│                           │ 選択中の設定 │
├───────────────────┤                           │             │
│ Tree              │                           │             │
│ Canvas: Pages階層 │                           │             │
│ Flow: Flows一覧   │                           │             │
└───────────────────┴───────────────────────────┴─────────────┘
Status      直近の操作結果。FlowのWATCH・処理ログはPreview中だけFlow面に表示
```

| 領域 | 表示するもの | 操作規則 |
|---|---|---|
| Header | 4つの表示形式 | 作業領域の配置だけを変え、選択と編集データを保持する |
| Context | 操作中の面、Page / slotまたはFlow、Preview状態 | 分割時の操作面が変わった瞬間に表示を更新する |
| Registry | ComまたはNode、検索、Library filter | ライブラリはフィルター。結果は平坦な一覧と境界線で表示する |
| Tree | CanvasではPagesとslot、Flowではトリガと名前の平坦なFlows一覧 | 左欄の見出しに「Canvas」か「Flow」を併記し、切替を明示する |
| Workspace | CanvasとFlow | 両者の選択は別々に保持する。分割時は最後に操作した面を強調する |
| Inspector | 操作中の面で選択したComまたはNodeの設定 | 各面の中で共通の幅と見出しを使い、内容だけを切り替える。縮小可能にする |

CanvasとFlowを作業領域の大外枠とし、Inspectorは操作中の面に属する設定欄とする。CanvasのDetailsとFlowのNode設定で幅・見出し・開閉操作を揃え、分割時は操作中の面の設定だけを表示する。Registry・Tree・Inspectorの縮小状態と幅は表示形式を変えても保持する。操作面の切替は面のクリックまたはキーボードフォーカスで確定し、マウスを通過させただけでは変えない。左欄とInspectorの操作は現在の操作面に属し、面の切替を起こさない。面名は色だけでなく文字と枠で示す。表示形式の変更では、単独表示なら表示した面を操作対象にし、分割表示なら直前の対象を保つ。未選択時には無関係な対象を出さず「Comを選択」「Nodeを選択」と表示する。

共通Inspectorの固定表示は十分な幅がある場合に限る。現行の左右分割は各面240pxを目安とするが、利用可能幅の半分まで下限を縮めるため、可読性の保証にはならない。提案では左欄の実幅＋各面の必要幅＋Inspectorの幅＋境界・余白から固定表示の可否を判定する。収まらない場合はInspectorを「設定」ボタンから開く一時的な重ね表示とし、閉じる／Escapeで元の対象へフォーカスを戻す。重ね表示中は背面への誤操作を防ぐ。ユーザーが選んだ4表示形式や左欄の縮小設定は自動変更しない。さらに狭い場合は各面内でスクロールし、単独表示への切替を案内する。具体的な必要幅は日本語の設定項目と拡大表示で検証して決める。幅による一時表示とユーザーの開閉希望を別に保持する。

## Canvasの追加・配置

「選択中のCom」と「追加先」を別の状態として扱う。Comを選ぶとInspectorの対象が変わる。追加先は`Page / Context`、`Page / Overlay`、`Container / Children`、`Button / Contents`、`Paragraph / Text`のように明示する。初期の追加先は表示中PageのContextとし、Treeのslot見出しをクリックすると追加先が変わる。詳細paneに追加先を選ぶボタンは置かず、Treeのslot選択とCanvas・Treeへの配置で指定する。

追加先はPage ID・Com ID・slot keyで保持し、名前変更や並べ替えに追従する。Pageを切り替えた場合はそのPageのContextへ戻し、その旨を表示する。追加先のComやslotが削除された場合は追加を無効にし、追加先を選び直す案内を出す。無通知でPage末尾へ追加しない。複数slotを持つComもTreeのslot見出しで追加先を指定する。

Registry上部とCanvasツールバーに同じ追加先を表示し、各カードの「＋」はそこへ追加する。追加できないComは無効状態と理由を表示する。ドラッグ中は候補のslotと挿入位置を強調し、`Page / Context / Container Com / Children・2番目`のような配置結果を手放す前に示す。配置後はそのComを選択し、結果をStatusに短く表示する。追加先は追加後も保持するため、同じslotへ続けて置くたびに指定し直す必要はない。

PageのContext / Overlayそれぞれの内部は縦方向を基本とする。PreviewではOverlayをContextへ重ねる。横並びは明示的なContainerのDirectionで指定する。配置操作で並び用Containerを自動生成しない。通常ContainerのDirectionが子の並び方を決め、追加・移動は配列順だけを変更する。既存の配置グループの表示は互換性のため保持する。

「位置を選ぶ」や配置方向メニューを設けず、Tabで対象へフォーカスを移し、Enterをクリックと同じ操作として扱う。Ctrl+Enterで見本・部品・Flow Nodeを掴む／離す。Ctrl+Shift+Pで仮想カーソルを切り替え、ON中は矢印でカーソルを動かす。キーを先に処理し、フォーカス中のLibraryやリサイズ操作へ渡さない。領域の端ではカーソル下の領域をスクロールし、PageUp / PageDown（Shift併用で横）でもスクロールできる。仮想カーソルと通常のドラッグは同じ配置・型制約を使う。Escapeで確定前の移動を取り消す。単一slotの置換には既存の確認を適用する。

## Flowの作成・接続

`+ Flow`は空のFlowを作る。空のGraphには「開始イベントを選ぶ」とEvent・Page Load・Scheduleの3つの選択肢を表示し、選択したときに初めてTrigger Nodeを置く。ComのEventsからFlowを作った場合は、対象ComをContextに示して「このComのClickを開始イベントにする」を表示する。この明示操作で初めてTriggerとCom参照を設定する。既存のClick Flowがある場合は重複作成せず、そのFlowを開く操作を示す。Nodeと接続をFlow作成時に自動生成しない。

Registryは検索とLibrary filterによる平坦な一覧を保つ。Nodeの用途が名前から分かりにくい場合は「開始」「条件」「値」「操作」の短い補助ラベルを各項目へ付ける。カテゴリフィルターの追加は、Node数の増加や利用者確認で検索の困難が認められた時点で検討する。Nodeをクリック追加した場合は空き位置へ置き、ドラッグ配置ではカーソル位置へ置く。NodeのOUTからドラッグ接続する方式に加え、OUTをクリックして接続先Nodeをクリックする方式と、Inspectorの出力先選択を同じEdge編集として扱う。接続可能なINだけを強調し、接続できない理由をその場に表示する。クリック接続中は起点とPort名を表示し、Escapeで取り消す。既存出力の付け替えは新しい接続先の確定時に行い、取消時は元のEdgeを保持する。循環やTriggerへの入力等、既存の接続制約を全方式で共用する。自由配置を維持し、`整理`を押したときだけ整列する。

Nodeの設定不足はGraph上の該当Nodeに印を付け、Inspectorに具体的な修正箇所を表示する。Flow一覧はトリガ・名前・設定状態を一行で示し、選択中Flowを明示する。CanvasのComを選ぶと、そのComを参照するFlowへEvents欄から移れる。

Previewの切替はCanvas・Flow双方の同じ位置に置き、状態を共有する。Breakpointの設定は既存どおり編集時に行い、Preview中は停止位置を確認する。Preview中だけFlowに実行位置、WATCH、処理ログを表示する。WATCHの値は編集定義へ保存せず、Password Maskが有効な入力値を伏せる。Browser Consoleの処理ログにも値を載せない。

## Inspectorの情報順序

Comは`基本`（名前、主要な値、ContainerのDirection等）、`内容`、`配置`、`見た目`、`イベント`、`詳細`の順にまとめる。基本項目は最初から見えるようにし、長い設定だけ折りたたむ。slotの子の順序と追加は引き続きTreeで扱う。Nodeは`入出力`、`設定`、`検証結果`の順にする。選択した対象の種類と名前は常に先頭へ表示する。

## 状態の境界

| 状態 | 内容 | 保持範囲 |
|---|---|---|
| ProjectDocument | Pages、Com、Flows、Node、Edge、設定値、Breakpoint | 編集定義。現在はメモリのみ、将来の保存対象 |
| EditorSession | 表示形式、操作中の面、CanvasとFlowの各選択、追加先、検索・filter、paneの幅と縮小状態 | Editorの操作状態 |
| PreviewSession | 表示中Page、実行位置、変数・定数の現在値、WATCH、処理ログ | Previewを閉じると破棄 |

この分離により、分割表示で片方を操作しても他方の選択を失わず、実行時のWATCH・VAR・CONST・FlowからのFIELD代入が通常編集へ混ざらない。追加先は選択中Comから暗黙に推測せず、明示したslotを唯一の基準にする。CanvasとFlowのRegistry検索・filterも別々に保持する。EditorSessionは開いているEditor内で保持し、再読み込み後の復元は今回の範囲外とする。

注意点として、現在はPreviewで手入力した入力値をComのValueにも反映しており、終了後も保持する（`App.svelte`の`previewChange`、`docs/flow-design.md`）。この入力値とFlowからのFIELD代入は挙動が異なる。今回の操作構造案ではこの仕様を維持する。手入力も完全に一時化する変更は別提案として扱い、全Preview値が終了時に破棄されるとは表示しない。

## 主な設計判断

| 判断点 | 推奨 | 理由と影響 |
|---|---|---|
| Registryの「＋」の追加先 | 明示したslotを使う | 選択中Comだけから追加先を推測すると、意図せずPage末尾や子slotへ入る。追加前に行き先を確認できる |
| 横並び | 明示的なContainerのDirectionで指定する | 配置操作から新しい階層を暗黙に作らない |
| Inspector | 各面の設定欄に共通の外観と開閉規則を使う | CanvasとFlowの大外枠を保ち、分割時も操作中の面の設定だけを表示する |
| 追加・接続操作 | ドラッグとクリックの両方を用意する | 操作の発見しやすさと精密な操作のしやすさを両立する |

## 実装順と確認条件

優先度P0は追加先の誤認防止、P1はクリックでの操作完結とFlowの導線、P2は配置構造の表示とInspectorの共通化とする。

1. **P0：操作中の面と追加先を可視化**：Context表示、選択と追加先の分離、Registryの「＋」の追加先表示。分割切替でも選択とfilterを保持する。
2. **P1：Canvasの配置を分かりやすくする**：ドロップ前に配置先・順序・拒否理由をCanvasとTreeへ示す。Tab・Enter・仮想カーソルからも同じ配置を行い、取消と単一slotの置換確認に対応する。
3. **P1：Flowの誘導と検証**：空のGraphの開始選択、Node単位の設定エラー、クリック接続と取消、Comから関連Flowへの移動を追加する。Comの主要設定も最初から見せる。
4. **P2：配置構造を見えるようにする**：横並びを明示的なContainerに限定し、自動レイアウト生成を外す。
5. **P2：Inspectorを共通化**：ComとNodeの設定欄の外観・縮小操作・幅を揃え、狭幅時は一時的な重ね表示にする。

受け入れ確認では、初めて使う人が説明なしで「Containerの子へButtonを追加する」「そのContainerを縦並びにする」「選択したComのClick Flowを作る」「分割表示でPreviewの実行位置を確認する」を試す。各操作の直前に対象と結果が読めるかを観察し、操作後のTree・Canvas・Flow・Inspectorが同じ状態を示すことを確認する。
P0で追加先をIDに基づく状態として定義した後、P1でドラッグとクリックによる配置を共通化する。Inspectorの共通化は既存DetailsとFlow設定のイベント・フォーカス・リサイズの責務を整理してから行う。新しい配置グループの自動生成は行わず、横並びは明示的なContainerで指定する。

| 確認対象 | 合格条件 |
|---|---|
| 4表示形式と左欄 | 切替後も各面の選択と検索・Library filterを保持する。RegistryとTreeを個別に縮小・復元でき、両方縮小時にも復元操作が残る |
| 追加先 | Containerを選択するだけでは追加先は変わらず、TreeでChildrenを追加先に指定した後の＋はその配下へ追加する。Containerは横並び・親の幅100%で始まる |
| 無効な追加先 | 対象削除後、別slotへ無通知で追加しない。単一slotの置換と型不適合が確定前に分かる |
| 配置の同等性 | 同じ対象と位置を指定したドラッグと仮想カーソルが同じ構造・順序を作る。通常ContainerのDirectionは変わらない |
| Flow作成 | + Flow直後はNode 0、Edge 0。開始イベントの明示操作後にTrigger 1、Edge 0となる |
| 自由配置と接続 | 追加・接続・取消で既存Nodeの座標は変わらない。整理時のみ整列する。付け替え取消で元のEdgeが残る |
| Preview終了 | WATCH・処理ログ・停止状態・実行用変数が消える。手入力保持とFlow代入破棄は現在の仕様どおりである |
| 狭い左右分割 | Inspectorで各面を押し潰さず設定を編集できる。閉じた後も選択・設定値・表示形式・フォーカス先が保たれる |
| キーボード | 面と対象を選び、追加・移動・接続・取消をドラッグなしで完了できる。入力中のDelete等が対象削除にならない |

初回の利用者確認では補助なしの完了可否、誤った追加先への確定回数、探し直した箇所を記録する。まず現在のUIでも同じ課題を実施し比較する。人数や時間の数値目標は観察前に断定せず、少なくとも上表の機能条件を満たしたうえで、誤配置が生じた導線を次の修正対象とする。
